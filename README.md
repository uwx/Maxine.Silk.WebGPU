# Maxine.Silk.WebGPU

[WebGPU](https://www.w3.org/TR/webgpu/) bindings for C#, plus prebuilt
[wgpu-native](https://github.com/gfx-rs/wgpu-native) binaries to run them on.

WebGPU is the successor to WebGL: the same API runs on the web and natively, over Dawn, wgpu and the
platform graphics backends. `webgpu.h` is the C surface all of those implementations share.

These packages are companions to [Silk.NET](https://github.com/dotnet/Silk.NET) 2.x and target the
same frameworks, so they can be referenced alongside `Silk.NET.OpenGL` and friends. They exist
because Silk.NET's own `Silk.NET.WebGPU` 2.23.0 was generated from a `webgpu.h` that has since changed
shape, and its native package carries a wgpu-native build old enough that 47 of the functions the
current header declares are missing from it.

The packages sit under a `Maxine.Silk.` prefix but the C# namespaces do not: the generated code
refers to `Silk.NET.Core` types by their full name without a `using`, so a namespace with a `Silk`
segment in it would shadow that and fail to compile. `using Maxine.WebGPU;` is the namespace; install
`Maxine.Silk.WebGPU`.

## Packages

| Package | Contents |
|---|---|
| `Maxine.Silk.WebGPU` | Core bindings (`WebGPU.GetApi()`, enums, structs, callbacks) |
| `Maxine.Silk.WebGPU.Extensions.WGPU` | wgpu-native's own entry points (`Wgpu`, e.g. `DevicePoll`) |
| `Maxine.Silk.WebGPU.Extensions.Dawn` | Dawn's additions (`Dawn`, e.g. `EmscriptenWebgpuGetDevice`) |
| `Maxine.Silk.WebGPU.Native.WGPU` | Prebuilt wgpu-native for `win-x64`, `win-x86`, `win-arm64`, `linux-x64`, `linux-arm64`, `osx-x64`, `osx-arm64` |

## Usage

```csharp
using Maxine.WebGPU;
using Maxine.WebGPU.Extensions.WGPU;

using var webgpu = WebGPU.GetApi();

var instance = webgpu.CreateInstance(new InstanceDescriptor());
// wgpu-native's extension entry points are not reached through GetApi's loader.
var wgpu = new Wgpu(webgpu.Context);
ulong index = 0;
wgpu.DevicePoll(device, true, in index);
```

`Maxine.WebGPU` looks for `wgpu_native` (`wgpu_native.dll`, `libwgpu_native.so`, `libwgpu_native.dylib`).
Reference `Maxine.Silk.WebGPU.Native.WGPU` to have the right binary copied next to your application;
otherwise put your own wgpu-native build on the loader path.

`TryGetExtension<T>` is not implemented — the generated `WebGPU` class has no extension loader over
there being no `wgpuGetProcAddress`. Construct the extension class directly, as above, and note that
both extension classes are thin wrappers over the same library: `new Wgpu(context)` resolves its entry
points from the context, not from the instance.

## Browser

`WebGPULibraryNameContainer` has no browser entry, because there is no `wgpu_native` file there.
Dawn's emscripten build provides the exports as imports instead, so a wasm build constructs the API
over a native context that resolves them (`WebGPU`'s only public constructor takes an `INativeContext`)
and never calls `GetApi()`.

Two things about that path are not obvious:

- Async. `emwgpuWaitAny` resolves against Asyncify, and `.NET` wasm has no JSPI. Use
  `CallbackMode.AllowProcessEvents` with a per-frame `wgpuInstanceProcessEvents` instead of waiting,
  which makes device creation a poll rather than a block.
- The canvas surface is Dawn's `EmscriptenSurfaceSourceCanvasHTMLSelector`, chained into
  `SurfaceDescriptor`'s `nextInChain` with `selector = { "canvas", strlen("canvas") }`. Its `sType`
  value lives on `DawnSType`, not on the core `SType` enum (see the repository layout note below).

## Generation

The bindings are generated by `tools/SilkGenerate`, a thin wrapper around
`Silk.NET.BuildTools.Program.Main`, from the headers in `build/headers`. Three of them, one profile:

| Header | Source | Project |
|---|---|---|
| `webgpu.h` | `webgpu-native/webgpu-headers` at `673658bc2bd70ec39fc55ebe6bb0173cf6d0a603` | Core |
| `wgpu.h` | `wgpu-native` `v29.0.1.1`, `ffi/wgpu.h` | `Extensions.WGPU` |
| `dawn-webgpu.h` | `emdawnwebgpu_pkg-v20260423.175430.zip` | `Extensions.Dawn` |

To regenerate:

```
dotnet run --project tools/SilkGenerate -- generator.json
```

A handful of requirements are silent or misleading when unmet, and one is worth knowing before
editing a header: every header becomes its own project, and `ProjectWriter` drops a non-core enum
whose native name the core project also declares. So `dawn-webgpu.h`'s extra `WGPUSType` and
`WGPUFeatureName` tokens never reach the generated tree, while the structs that carry them do. The
values are redeclared by hand in `src/Extensions/Maxine.WebGPU.Extensions.Dawn/DawnSType.cs`; add to
that file when a header adds one.

## Repository layout

```
src/Maxine.WebGPU/                        Core bindings (generated + hand-written)
src/Extensions/Maxine.WebGPU.Extensions.*/ One project per implementation's extra entry points
native/Maxine.Silk.WebGPU.Native.WGPU/    wgpu-native binaries, committed per RID
build/headers/                            Pinned upstream headers
build/                                    Type maps, generator cache, licence header
tools/SilkGenerate/                       Runs Silk.NET.BuildTools over generator.json
```
